# 回路、回路名称与配电系统迁移

统一入口为 `revit_workflow_run`，工作流 `electrical.circuit`。它迁移旧版 `create-circuits.csx` 与 `name-circuits.csx` 的受控业务意图，但不迁移固定文件路径、固定 14/3/27 数量、按标记隐式分组或自动保存。

## 领域输入

- `circuits`：明确的既有元素 `elementIds`、`panelId`，可选 `switchIds` 和 `name`。本细分工作流不接受 `@引用`；同批新建灯具/配电箱的引用组合仍使用 `lighting.full`，不混为已验收的相同范围。
- `panelDistributionSystems`：明确的 `panelId` 与当前项目原生 `DistributionSysType` ID。
- `parameterChanges`：只允许 `BIP:RBS_ELEC_CIRCUIT_NAME` 的字符串值，或 `BIP:RBS_FAMILY_CONTENT_DISTRIBUTION_SYSTEM` 的当前原生类型 ID，不能传任意参数名或错配值类型。
- `panelSchedules`：仅 `panelId`、可选 `id` / `name`；预读配电箱原生类别。`tags`、`dimensions` 沿用结构化操作接口，并继续经过统一计划校验。

助手应先从当前模型读取真实元素 ID，不要求用户手写 JSON。旧脚本中的办公室、过道/楼梯间、会议室标记规则只作为迁移参考，不是新版的默认设计规则。

## 预览前检查

1. 输入严格校验：ID 明确，回路操作 ID（含自动编号）不能重复；负载和开关跨回路互斥预留，不能兼任任何回路的配电箱。同一配电箱可以服务多个不重叠回路。
2. 分批调用 `revit.inspect`，每批最多 100 项，缺失、重复或截断立即停止。
3. 配电箱必须是 `OST_ElectricalEquipment` 族实例；配电系统必须是原生 `DistributionSysType`。
4. 回路负载和开关必须是族实例并暴露可核验的电气连接器；开关必须属于 LightingDevices。成员状态必须是已读原生 `systemIds` 数组，未知不能当作未分配；负载或开关已分配均拒绝静默重分配。电气连接器域不认证 PowerCircuit 分类、电压或工程容量，原生执行仍须校验。
5. 既有回路改名和两种配电系统输入路径均核对内置参数存在、唯一、类型正确、可写、基线可读，返回 `before` / `beforeHasValue` / `after` / `noOp`；配电系统参数路径也必须预读目标 DistributionSysType，不能只检查配电箱。已知空值与未知分开处理。
6. identity、revision、路径和保存状态变化时不创建计划；不自动重试。

## 计划顺序

计划按以下顺序生成：

```text
设置配电系统 → 修改明确的既有回路名称 → 创建明确成员回路 → 创建配电盘表/其他文档对象
```

所有写入仍是预览 → 聊天确认 → Revit 单事务 → 原生收据/核验 → 手动保存。Revit 不弹第二次确认，不自动保存。

`ask` 模式只询问回路成员、开关、配电箱、名称和配电系统，不访问 Revit。`assisted` 必须披露假设，只生成候选预览；不会根据样板或警告猜测回路成员、容量、保护配合或三相工程意图。

## 新回路创建验收

当前采用一个最小真实应用场景，而不是测试文件默认点位：在明确审阅的现有空房间内，使用当前项目已核验的 WorkPlaneBased 灯具类型放置一个新灯具，并创建一个明确接入既有配电箱的 PowerCircuit。计划不创建导线、不自动保存。

提交后的只读核验要求：

- 新灯具类别、族类型、标记和 XYZ 与预览一致；
- 新回路为原生 ElectricalSystem，负荷名称、配电箱和成员关系正确；
- 灯具与回路、配电箱与回路的原生关系双向可读；
- 灯具数量和回路数量各增加 1，导线数量不变；
- 提交收据包含稳定引用，`saved=false`；
- 失败时不自动重试，必须读取计划和当前模型状态。

2026-10-09，用户在聊天中确认该具体计划后仅提交一次。原生回执返回一个新灯具和一个新回路；独立读取确认灯具类型、标记及 XYZ 与预览一致，回路负荷名称正确、成员仅为该灯具、配电箱分配关系正确，未创建导线。提交后用户手动保存，保存后只读核验通过：identity/revision 保持一致、`isModified=false`、`saved=true`，灯具/回路/配电箱原生关系和计划状态均匹配。原生回路 `summary.name` 是回路编号，计划中的 `name` 对应 `electrical.loadName`（负荷名称），两者不能混同。私有计划/模型/元素 ID、点位和完整证据仅存放于 Git 忽略的 runtime，不写入公开文档。只认证当前会话的已读范围，尚未认证关闭重开后的磁盘持久性；未自动保存、重试或再次确认。

该证据只覆盖“一个明确灯具 + 一个明确配电箱 + 一个新回路”的受限场景，不代表旧版固定批量回路规则、不同配电系统写入、导线创建、配电盘明细表或完整照明工作流已经功能对等验收。

实际使用 `lighting.full` 的同批新元素引用路径。共享的原生 `create_circuit` 操作有实机证据，但 `electrical.circuit` 以既有未分配成员创建回路的适配器路径仍需单独验收，不能由本测试替代。

随后复查发现另一次原生“设置墙工具”事务：revision 增加，当前 `isModified=true`。只读重新核对的119项电气快照与提交后快照一致，但当前文档不能再标为已保存。历史保存核验与最新保存状态分开记录；空的原生事件元素列表不证明无全部副作用，也不能解除 revision 保护。没有自动保存或再次提交计划。
