# v0.3.22 局部碰撞/净距只读核查

## 状态与边界

2026-10-05 已实现并通过编译、核心测试与 MCP 契约测试；**v0.3.22 原生查询契约已在2026-10-06复核；当前路线并非无碰撞，见下面的真实结果**。

新增 `revit_collision_check`（逻辑 API `revit.collision.check`）。它不创建临时模型元素、不打开事务、不改变活动视图/选择集、不自动保存。普通用户不需要为这次只读查询进行模型写入确认；任何避让仍另行预览和确认。

## 输入

- 当前 `documentIdentity`，可选 `expectedRevision`（建议始终提供）。不匹配即拒绝。
- `targetElementIds`：1—50 个当前文档中真实存在的模型实例 ID。
- `excludeElementIds`：可选，最多500个真实模型实例；不允许与目标重叠。
- `candidateCategories`：可选，默认机电设备/管道/管件/风管/风管管件，以及墙、楼板、柱、结构梁/基础、天花和屋顶。空数组使用同一显式默认集合。
- `clearanceMm`：可选，0—10000 mm；默认0。不得替用户选择维护标准。
- `toleranceMm`：可选，(0,10] mm；默认0.1，体积阈值为 `max(1,toleranceMm³)` mm³。
- `maxCandidates`：可选，1—1000；默认500，为附近唯一候选元素数，不是每个目标可无限重置的上限。

不接受未知字段、猜测的 `@reference`、不安全整数、重复ID、重复类别、字符串数值、负数、NaN/Infinity。

## 三种证据

1. `exact-solid-intersection`：完整可读的原生实体对布尔相交，最大实体对的交集体积严格高于阈值。返回类别、双方ID、交集体积及可读时的近似交集中心。体积是最大实体对证据，不是多实体重叠的精确合并体积。
2. `expanded-bounding-box-candidate`：用户提供了大于0的净距且扩大包围盒相交，但完整实体检查未发现高于阈值的交集。这只是保守候选，**不证明精确净距合格或不合格**。
3. `unknown`：实体缺失、部分几何、Mesh、无效边界、实例变换失败或布尔运算失败。不转换为无碰撞或未连接。

范围与完整性也必须一起阅读：`scope` 明确不包含链接模型、保温层和 fabrication parts；候选/几何限额可能导致 `truncated=true`，`diagnostics.complete` 只针对已声明范围，不代表工程合规。

## 防漏检范围规则

`targetElementIds` 整组和显式排除元素不会被视为外部障碍物。**组内不做互检**：若把水泵和整条路线都作为一组目标，不能借该结果宣称水泵与回折管段互不相交。

本次泵房验收应逐个目标执行：

- 先查询水泵的真实连接 peers，仅显式排除正常直接连接的管段，再检查水泵与其他回折管段。
- 随后逐段检查回折管段与附近设备/其他障碍物。排除表来自当前原生 peers 或人工审阅，不自动全盘排除整条路线。
- 工具自身不会盲目读取 Pipe ConnectorSet 或自动跳过所有已连接构件。未知连接关系不生成“正常邻接”的假定。

## 算法与资源限制

- 宽阶段只做声明类别的边界库存与 Revit 原生包围盒快速筛选；空间遥远的候选不读取实体。
- 处理 BoundingBoxXYZ 的变换和全部8个角；布尔之前再以每个实体的实际包围盒缩小配对。
- 递归读取 GeometryInstance 的 SymbolGeometry，并累乘实例变换；SolidUtils.CreateTransformed 只创建内存中的几何副本，不创建模型元素。
- 缓存已读取元素，释放内存副本，候选按ID确定性排序。
- 几何上限：每元素128实体、4096几何对象、递归16层；最多5000个目标/候选配对、10000次实体配对和20秒查询预算。配对上限独立于候选元素上限，超出时标记pairTruncated以控制返回结果大小。
- 宽阶段最多20000个边界库存元素；缺失边界无法定位时报告“proximity-unknown”。最多返回100条边界未知明细，超限标记截断；不可用边界不能静默判通过。
- 超出时间预算或取消返回错误，不把此前的部分工作当成完整报告；超出实体配对/候选限制则显式标记未知/截断。

## 只读实机验收

提供可重复脚本 `mcp/collision-acceptance.mjs`。输入文件由助手根据当前查询准备，用户不需要填写或记住元素ID。

输入包含明确的 `expectedProjectPath` 与工具请求字段；脚本在调用前读最新 identity/revision，不复用上次会话。输出必须是新的本地证据文件，不覆盖旧证据。

核验：

- 真实加载能力、目标实例存在且类型/原生数据不变；
- identity/revision、类别数量、保存状态、视图和选择集前后一致；
- 三类证据标签、阈值、排除表和截断状态一致；
- 结果 `PASS_READ_ONLY_COLLISION_CONTRACT` 只表示查询契约通过，**不代表无碰撞**。

首次实机用 `clearanceMm=0`；只有用户指定维护净距后才运行正净距值。运行前后不自动保存、关闭Revit或执行任何建模计划。

## 2026-10-06 v0.3.22 真实只读核查结果

- 同一测试副本重新打开后，重新读取identity/revision和真实端口，逐个检查水泵、既有管道、四段新增管道和四个管件。10次查询均通过15项只读契约检查，结果没有截断。
- 水泵2295837与变径件2295876是唯一已证实实体碰撞对；两个方向交集体积约948.732/948.733 mm³。这是一个碰撞对，不是两个；体积为最大子实体对证据，不是实体并集体积或穿透深度。
- 水泵2295837与回折管2295869是唯一未能判断对；两个方向都抛出 InvalidOperationException。原生结果明确complete=false，不能据此判定无碰撞。
- 查询前后文档identity/revision、保存状态、原生路线参数/几何/peers、管道和管件ID集合、活动视图及选择集保持不变。没有修改或保存模型，原有8条流向/流量警告保留。
- 实机拒绝测试通过：过期identity、错误revision、重复ID、缺失元素分别被拒绝；没有绕过保护。
- 正净距值未由用户提供，因此本轮clearanceMm始终为0；没有进行维护净距合格判断。

## v0.3.23 Boolean 失败诊断

布尔相交失败仍归入unknown，不会转为无碰撞、净距通过或自动重试。本次只修复错误上下文丢失：新增可选details，包含异常完整类型、清洗并截断至1200字符的原生消息、截断标志、失败实体索引/数量和两侧项目坐标实体边界。诊断只作为数据，不当作助手指令；不返回堆栈、不执行几何偏移、不改变tolerance。

bridge.info 新增 collision-boolean-diagnostics。原collision-check能力的旧版只读接口继续兼容，但不能声称已经取得新版诊断。验收脚本仅在原生声明新增能力时强制检查details字段；不以MCP脚本版本替代Revit已加载版本。

最小实机复现已将范围缩小至回折管2295869与OST_MechanicalEquipment，连续两次返回同一unknown且缺少原生details。源码诊断回归测试先失败后通过，5项核心测试与MCP透传测试覆盖长度限制、异常上下文和保留unknown。原生布尔失败根因还未知；新版需重启后再跑同一对验证诊断，不能声称问题已经修复或路线已避让。
