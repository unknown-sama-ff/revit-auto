# 既有轴网创建的最终原生回读补齐

沿用既有单能力迁移与原生回读方案，补齐 `structure.grid-creation` 的实现缺口；不增加新的建模操作，不改变房间和四墙夹具的阻塞结论。

## 范围与选择

目前 `CreateGrid` 只在创建时核对名称和直线端点；与柱、墙、楼板和房间不同，后续操作及事务提交处理后的结果没有再次核对。继续只在创建时检查会漏掉后续漂移；全面重写结构适配器则会重复已有柱回读。本次采用最小补齐：保存原始操作和原生 ID，复用统一的提交前/提交后回读边界。

## 契约

- 仅接受既有 `create_grid` 契约中的具名水平有界直线。名称必须严格相等；允许整段端点方向反转，每个端点的三维距离容差仍为 0.01 mm。
- 纯规则拒绝非有限坐标、曲线、无界线和任意名称/端点漂移；原生服务读取实际 `Grid.Curve`，不从 preview 或历史快照填充实际值。
- 每个创建的轴网绑定原始操作的独立 JSON 副本、原生元素 ID 和原生文档。在整个计划执行完成后、事务提交后且事务组归并前，分别重新读取；丢失、换类、跨文档或漂移都抛错，走现有整体回滚路径。
- 创建回执保留首次原生回读，最终回执增加 `gridCreationVerification`，明确阶段、已验证数量和逐项原生结果。副作用、保存、持久化、视觉和工程合规仍为未验证。
- 能力指纹增加 `grid-creation-readback`，以区分只包含原创建即刻检查的旧 DLL。没有注册或实载证据前只记录为代码/编译完成。

## 实施与验证

1. 添加纯规则及 CoreTests，覆盖端点反转、默认 Z、有限性、容差边界和各独立字段漂移。
2. 原生 `ArchitectureService` 复用纯规则；`ModelExecutor` 保存绑定并在两处提交边界回读，router 归档最终结果。
3. MCP 集成守卫检查提交顺序、回滚窗口和保守验收标志；运行 CoreTests 和 MCP 测试。
4. 用新的版本化目录隔离编译 Revit 2027.3 DLL，并运行安装 `CheckOnly`；保存构建摘要和证据。
5. 更新任务卡和队列，保持旧实机验收结论。下一轮如需实机使用，再对具体构建注册、人工重启及新会话只读基线。当前不创建计划、不写模型、不保存或重启。
