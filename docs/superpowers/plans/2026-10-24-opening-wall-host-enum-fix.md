# 原生墙洞口宿主枚举修正

沿用已批准的洞口契约：仅接受直立、直线 Basic wall，不新增建模种类，不放宽宿主限制。本次修复是在宿主只读审查中发现的具体实现错误，不改变已批准设计。

## 证据与根因

最近已验收的原始快照中，18 面墙的 `WALL_CROSS_SECTION` 参数值均为1，格式化文本为“垂直”。直接读取当前 Revit 2027.3 API 程序集元数据确认 `WallCrossSection.Vertical=1`、`SingleSlanted=0`、`Tapered=2`。现有 `OpeningService.Validate` 使用 `AsInteger()!=0` 拒绝墙宿主，误把单斜墙的枚举零值当作直立墙。该条件会误拒绝合法直立墙，同时可能放过水平定位线的单斜墙。

SDK 原始元数据证据位于 `.tmp/opening-wall-cross-section-api-20261024.json`。候选测试墙 `2296040` 来自最近完整只读快照：100 mm 非结构墙，1F，定位线 `(70000,60000,0)` 至 `(75000,60000,0)` mm，高3000 mm。候选洞口为 `(72000,60000,1000)` 至 `(73000,60000,2000)` mm，1000×1000 mm，宿主容差1 mm。这里只登记离线候选，当前宿主依赖/包围盒和原生预览均未完成，不认证空闲、净距或工程合规。

## 实施步骤

1. 新增宿主接线回归，先在旧 `!=0` 实现观察失败；保留 SDK 枚举、模型原始参数及旧源码摘要。
2. 将比较改为 `(int)WallCrossSection.Vertical`，并要求原生参数存在、Integer、HasValue；保留 Basic、直线和水平定位线约束。
3. 运行 CoreTests、洞口/建筑/轴网定向 MCP 和完整 MCP 测试，再用 Revit 2027.3 API 编译到新的独立版本目录并执行安装 CheckOnly。
4. 更新洞口说明、队列和进度，记录新 DLL/MVID、来源/日志摘要和待验收边界。

本轮不注册或重载插件，不创建原生洞口计划、不 Confirm、不写模型、不保存、不重启。当前已加载 DLL 不被覆盖；修复构建的具体注册仍需独立申请和批准，之后再做当前宿主的只读复核及单洞口验收。全部历史系统副作用、保存重开和原归档结论保持。
