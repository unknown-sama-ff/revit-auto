## 固定范围与预检

预览绑定当前文档 identity、revision、保存状态、固定路径、文件大小与 SHA-256，以及原 Revit PID、启动时间、可执行文件路径/摘要、27.3 版本和插件 MVID。具体模型路径、原生 ID、完整快照、进程及注册指纹留在 Git 忽略且限制访问的 runtime，不写入公开设计文件。不能用 basename、标题或相同路径代替会话身份。

首版只接受事先登记的当前测试副本，登记不会使整个 acceptance/models 目录成为可执行白名单。路径必须为现有本地绝对 .rvt 路径，最终文件身份与登记文件一致；拒绝 UNC、云路径、映射网络盘、目录链接/文件重解析别名、空路径、只读文件以及无法确认类型的路径。执行接口只接收既有请求 ID 和固定摘要，不接受新的文件路径、exe 路径、任意命令或另存为目标。

原生预检必须确认：

- 活动项目是该固定副本且为唯一非链接主文档。首版有其它主项目或族文档就停止，即使其它文档已保存；链接文档只登记，不单独保存。
- 不是工作共享、云模型、分离中心模型、族文档、链接文档或只读文档；拒绝编辑模式、活动事务和不可验证的文档状态。
- 无正在执行或排队的桥接写入，无本插件退出排队状态；待处理模型计划需要显式披露，未解决的 pending/executing 计划阻止生命周期执行。无法枚举全 Revit 或其它插件的 pending command；CanPostCommand 预检和实际 PostCommand 都须失败即停止，不能宣称全局队列为空。
- 当前文档、完整已读范围、进程和插件与预览一致；任何身份、revision、路径、保存状态或模块变化使预览失效。

预览有效期为 10 分钟。用户审阅一个具体生命周期预览后，保存、退出和重开由同一请求的各个阶段推进；不要求用户逐阶段重复批准。软件实现批准不等于具体构建注册批准，也不等于未来任意模型写入批准。

## 组成与接口

`v27/DocumentLifecycleRules.cs` 承担严格字段、状态和范围验证；`DocumentLifecycleService.cs` 负责 UI 线程上的原生预检、保存、正常退出排队和固定文件打开；`DocumentLifecycleEvents.cs` 记录保存、对话框、文档变更/关闭/打开及退出事件，形成有界证据。与现有服务保持同一错误和响应预算模式，不新增任意 C# 或脚本执行入口。

桥接提供独立的 prepare/get/verify_scope/save_once/post_exit_once/open_saved_copy_once 路由及 `local-test-copy-lifecycle` 能力。prepare/get/verify_scope 是只读查询；其余明确标记为非只读、不可自动重试。原生和 MCP 都拒绝未知字段、非法 ID/revision/摘要与跨阶段请求；原生从未折叠的 JsonElement 拒绝重复字段。标准 MCP SDK 在 handler 前先 JSON.parse，不能承诺 stdio 重复键检测；MCP 对解析后的对象严格校验并以唯一键 JSON 序列化转发，不另增传输解析器。缺失能力时在发送动作前拒绝。动作只使用预览已经绑定的目标。

prepare 不保存、不退出、不打开项目，也不备份 RVT或取得执行租约；只返回预检、阶段、目标摘要、有效期、限制和预览证据。get 只读既有请求的状态。获批 execute 在 BACKUP_VERIFIED 后、保存末次原生预检之前，原子取得执行租约并再次检查待执行队列，租约失败就停止。保存、退出、打开各阶段先持久化独立单次 attempt，再调用 API；再次收到同一阶段动作只返回既有状态，不调用 API。阶段相同但摘要不同必须拒绝。

生命周期请求使用稳定 operationId 和请求 SHA-256，不能使用每次 TCP 交换新生成的 requestId 作为幂等标识。桥接信息读取后的预检不能替代原生动作入口再次校验 PID、identity/revision、路径和阶段。监督器须与 Revit 使用同一 Windows 用户和交互会话；固定 REVIT_AI_CONFIG 的路径、内容摘要和 ACL，遇到访问拒绝仅请求该动作所需权限，不改 ACL、重新安装或复制凭据，日志中不能写 token。

`App.cs` 订阅并解绑所需生命周期事件；`Infrastructure.cs` 在生命周期租约生效时暂停其它文档相关命令，并在退出排队后立刻结束当前 ExternalEvent，不能继续本轮最多四项的后续 dispatch。允许生命周期状态、桥接信息及绑定租约的 verify_scope 读取，不临时释放租约进行核验。不把冻结描述为能够阻止其它插件或用户的原生操作，原生状态变化仍须被检测并导致停止。

verify_scope 只接受 operationId、请求摘要、合法阶段及固定读取索引；其查询配方在预览中绑定，包括 context、分页类别/类型完整成员、已声明 inspect 范围及四根依赖关系。不得从动作参数新增 category/elementId/query/任意方法。每次读取及末次核验都检查租约目标和对应 identity/revision，分页有完整性及总量上限；原生调用复用既有只读服务和完整 schema，MCP 复用现有允许排序/负零的比较规则，保留所有字段和有序几何。阶段结束前后各一轮，不能用 context 中受限类型样本替代完整分页集合。

请求终止后永久撤销该 operation 的后续动作许可，终态不能重新批准或恢复继续。保存未排队退出时，待原生 API 返回空闲后解除桥接执行租约，取消尚未执行的动作而不无限阻止未来用户操作；已经 EXIT_POSTED 则保留租约至退出，或用户明确人工恢复当前会话后解除。不因租约解除自动重试、创建新请求或继续退出。

`mcp/document-lifecycle.mjs` 提供严格 MCP 契约和预览校验，现有 `bridge.mjs` 只增加能力门禁。外部监督器负责文件备份/摘要、进程生命周期和持久化验收，不能从后台调用 Revit API。监督器使用一个排他请求租约与固定进程句柄、PID/启动时间，重开阶段只能使用预先核验的 Revit 可执行文件。

首版外部入口为 `tools/test-copy-restart.ps1`，prepare 与 execute 分离。execute 接受已审阅请求的固定摘要，并在任何原生动作前写单次流程 attempt；launch marker 单独在实际启动阶段写入。监督辅助进程隐藏运行，Revit 使用其正常可见交互窗口；使用结构化进程参数启动空 Revit，等待新插件握手后经受控 ExternalEvent 打开登记副本，不依赖尚未验证的命令行文件打开参数。

## 执行阶段

| 阶段 | 必须具备的证据 | 失败后行为 |
| --- | --- | --- |
| PREVIEW_READY | 绑定目标、范围、进程、插件、有效期和已披露限制 | 只读停止，不创建替代动作 |
| BACKUP_VERIFIED | 执行批准及请求摘要；磁盘 RVT 的独立只增备份、大小与哈希匹配 | 无保存请求，保留原因 |
| SAVE_STARTED | 原生末次预检与持久单次保存标记 | 不重发保存，查询现有结果 |
| SAVE_VERIFIED | 成功保存事件及当前无待保存修改；或明确已保存 no-op；两轮完整范围、文件摘要稳定 | 不退出 |
| EXIT_POSTED | 再次预检、稳定保存证据、单次退出标记，PostCommand 排队证据 | 不重发退出 |
| OLD_PROCESS_EXITED | 绑定进程句柄正常退出，无停止原因；磁盘文件仍等于 SAVE_VERIFIED | 不启动新进程 |
| NEW_PROCESS_READY | 单次启动记录、新进程的启动时间/路径/版本/插件握手均匹配 | 不再启动；保留新进程现场 |
| OPEN_STARTED | continuation permit 与新进程复核通过；持久单次打开标记，无其它主文档或原生事务/事务组 | 不再次打开，核对现有结果 |
| REOPEN_VERIFIED | 单次固定文件打开；新 identity、revision=0、isModified=false；文件及两轮完整已读范围核验 | 报告限定失败，保留现场 |

RVT 备份只复制现有磁盘字节，不宣称包含尚未保存的内存修改；不能自动用备份覆盖原文件。备份与所有动作标记必须在 API 动作前落盘，文件存在即拒绝覆盖。保存失败或保存结果未知时，自动流程不退出也不再次保存。

若预检时 `isModified=false`，不调用 Save，标记 `saveAction=noop_already_saved`；仍完成文件/范围核验。该路径只能证明重启与既有保存内容，不能被记为“自动保存写入已实机验收”。真正有修改的保存路径调用一次 `Document.Save()`，不创建模型事务，不使用 SaveAs/同步中心或猜测保存选项。成功要求匹配的 DocumentSaved 成功事件、无对话框/停止原因、会话/路径/revision 保持一致且 IsModified=false，再核验已读范围和文件。保存文件摘要不要求一定变化，但必须读回有效且稳定；原生事件中的意外模型变化或取消一律停止。

退出只能一次 `PostCommand(ExitRevit)`，并以自然退出观察作为阶段依据。返回 `EXIT_POSTED` 不是退出成功；TCP 回执可能与退出竞态，断连不是成功或失败证明。没有完整可读取退出证据、事件日志未闭合、出现弹窗、超时、进程身份变化或文件哈希改变时，不启动新 Revit。旧进程正常退出结果及固定端口释放均须验证；如果固定端口已被其它进程接管，停止，不连接或改变端口配置。

外部监督器只在旧进程自然退出后单次启动新进程。新进程握手不接受旧 PID、重用 PID 的不同启动时间、错误 exe/版本/MVID或其它 Revit 进程抢占的桥接连接。打开前再检查磁盘文件，原生打开接口只接受对应的单次重开许可；有其它活动主文档时停止。打开后核对新会话及稳定已读范围，不能复用旧模型计划或旧会话身份。

固定文件打开拟采用 `UIApplication.OpenAndActivateDocument` 的 ExternalEvent 路线，须在实际 27.3 API 编译与受限实机验证中确认。不能从 Idling、ApplicationInitialized、DocumentOpened 或其它嵌套原生事件直接调用，也不能在任何事务/事务组仍打开时调用。Autodesk 早期官方说明提供 ExternalEvent 例外，但不是当前 27.3 已验收证据；若当前版本拒绝该路线，停止在打开前并保留人工打开步骤，自动重开分支保持未完成，不临时换用未核验的 CLI、Journal 或 UI 点击。

普通重启要求新旧 MVID 相同；若用于已批准插件切换，另绑定现有注册请求/回执以及批准的新 DLL 摘要和 MVID。没有这一独立批准不能借重启更换插件。现行 registration-switch 的具体构建批准与保护配置检查继续使用。

跨进程状态不使用旧会话内存。原批准请求是带固定 SHA-256 的不可变文件，各阶段为只增记录并绑定前一阶段摘要，事件日志有序号、总量上限及结束摘要；状态 get 只能读取并验证这些记录。监督器确认旧进程自然退出且退出证据完整后，写单次 launch 记录；观察新进程真实启动信息后，写单次 continuation permit，绑定原请求摘要、SAVE_VERIFIED 文件摘要、退出与启动证据，以及新 PID/启动时间/exe/MVID。固定 runtime 文件名从合法 operationId 派生，不接受客户端文件路径。

新插件的 get/open 只能恢复此许可的生命周期状态，经 OS 进程身份和全部摘要核对后打开登记副本；不恢复旧模型计划或文档会话。目标会话 identity 由打开后的原生文档生成并另存新阶段记录。取消、超时、unknown、日志失败或停止原因都是终止状态，禁止生成继续许可。原插件卸载前的结束记录只证明受控事件记录已闭合，仍须监督器核对旧进程正常退出结果；缺失任一项就停止。

OnShutdown 先阻止新生命周期动作、停止接入并拒绝剩余队列；保持对话框/文档事件监听至结束记录落盘和 flush 完成，随后解绑事件并释放资源。日志闭合不证明本插件卸载之后其它插件或系统没有事件，进程退出状态与文件摘要仍须独立核对。DocumentOpened 监听在新进程打开任何文件前完成；打开事件引入的修改照实记录，不能重置 revision 或 session 来满足 revision=0 的验收条件。

## 弹窗、超时与未知结果

“停止”意味着停止后续自动动作、保留 Revit 当前状态与弹窗并输出原因；不承诺能够中断同步保存、撤回已排队退出或消除弹窗。不能用 OverrideResult、快捷键、模拟点击、自动放弃修改、Stop-Process 或任务结束来完成流程。

保存前 deadline 预检，保存返回后再核对 deadline；Save 没有 CancellationToken 参数，超时不能证明没有保存。超时或丢回执进入 `SAVE_OUTCOME_UNKNOWN`，只能读取持久事件/状态/磁盘证据，不能再次保存或继续退出。

打开阶段的丢回执、超时或证据不完整同样进入 `OPEN_OUTCOME_UNKNOWN`，不再次打开，也不自动关闭已经打开的文档。UNKNOWN、FAILED、STOPPED、CANCELLED 均为不可继续的终态；后续人工恢复只能读现有结果，若另做动作必须形成新的有效预览。

退出阶段最多等待 120 秒，启动/插件握手/重开阶段各最多 180 秒，保存阶段观察预算 120 秒；这些是自动继续条件的截止时间，不是原生 API 的硬中断。保存启动须在预览的 10 分钟期限内，启动后各阶段用单调时钟分别计时；系统时钟倒退或不能验证预览有效期时停止，不延长或重建许可。监督器每 1 秒检查一次，用户可中止监督器；实现不能用一个超过 60 秒的阻塞等待阻止状态汇报。取消同样停止后续步骤，不强杀 Revit，也不自动重试。

对话框事件只能记录不能取消。事件日志写入失败、日志超限或遗漏结束标记都视为证据不完整并停止。Revit 未报告的其它插件/系统窗口不能被宣称完全覆盖；窗口阻塞/无响应最终由阶段超时停止后续步骤，禁止保证“绝无弹窗”。事件处理程序不修改任何文档。

同步保存或弹窗可阻塞 ExternalEvent 与 get 查询；监督器须直接只读检查该 operation 的持久只增事件/stop 文件，验证序号、schema、摘要及已完成记录，不能仅等待 API get 响应来检测停止。读取失败或损坏就停止后续步骤，不补造事件或猜测弹窗选择。

## 验证与交付

纯规则测试覆盖路径/版本/文档状态、固定身份和摘要、过期预览、阶段非法迁移、重复动作、未知结果和跨会话拒绝。事件/队列测试覆盖保存取消、弹窗、额外文档、用户或其它插件引入修改、冻结后队列、退出后立即结束 ExternalEvent、丢回执及日志失败；模拟进程测试覆盖 PID 重用、旧进程未退出、错误握手、启动失败、单次打开、文件变更和取消。

MCP 契约测试覆盖非只读标记、严格 schema、旧插件拒绝、无动作预览、单次阶段、故障不重试。完成 CoreTests、MCP 全量回归、实际 Revit 2027.3 API 隔离编译及安装 CheckOnly，再独立复审具体构建，生成可批准的注册请求。保留 2025 DLL、客户端配置与桥接凭据/ACL。

实机先验证已保存 no-op 的重启重开，再另行准备有待保存修改的受限保存预览与批准，验证真实保存分支；不为了制造修改而擅自移动 AL1、复制类型或修改模型。人为制造弹窗、失败和回滚的测试亦须受控，合成测试不能代替真实保存验收。

当前插件尚无生命周期能力，新版首次加载需要一次人工重启；此引导不能由尚未加载的能力自动完成。软件设计/实现批准、具体构建注册批准和实机生命周期预览批准分别记录，已经给出的范围选择不要求重复询问。最终只能标记所测分支和已读范围，不改变既有 unresolved 与整体副作用限制。
