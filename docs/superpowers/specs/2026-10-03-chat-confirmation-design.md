# 单次聊天确认设计（用户已批准）

用户要求去掉 Revit 二次确认，并于聊天中确认方案后回复“继续”。执行行为改为：只读查询无需确认；所有建模/导入写入仍先生成计划，由用户在聊天中明确批准该计划，然后助手调用一次 commit。Revit 不再弹确认，不增加新的授权布尔字段，不对同一未修改的批准计划重复提问。

保留当前文档身份/修改版本、类型/单位/宿主/连接器验证、计划过期、取消、重复提交收据、单队列、事务回滚和不自动保存。候选图纸/图片仍需审阅，但审阅结果进入同一聊天确认链路，不另设 UI 批准。

授权信任边界：MCP 客户端负责核实用户聊天确认，Revit 后端不能读取聊天内容。不是独立身份认证系统。普通事务警告记录后返回聊天，错误/文档损坏中止回滚。主动点击的连接状态、OS 权限提示和 Autodesk/其他插件信任或授权提示不属于重复建模确认，不绕过。

兼容与部署：桥接 info 声明 confirmationMode=chat。新版客户端向旧版写通道请求 commit 时在版本预检查阶段拒绝，不发送模型写入；旧版只读仍可用。新程序集输出到独立 chat 目录，保留旧 DLL，更新清单后让用户保存并手动重启 Revit。实现测试不得修改当前项目。

验收：提交无 TaskDialog；plan/import 工具只接收 planId；预览响应声明需聊天确认而无需 Revit 确认；失效/取消/重复保护不变；旧版写阻断与只读兼容；警告返回/错误回滚逻辑保留。通过编译与自动化测试不等于真实模型写入已验收。
